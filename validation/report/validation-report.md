# 測定モデルとしての検証レポート

`src/lib/engine` の実装をそのまま呼び出し、**真の特性値が既知の合成回答者**に対して回して測定した結果です。
抽出（Claude）は誤りゼロの理想的な抽出器として模擬しているため、ここに出る誤差はすべて計算式に由来します。実運用の精度はこれより悪くなります。

再現方法: `npm run validate`（乱数はすべて固定シード）

## E3. Confidenceが高いほど推定は正確か（キャリブレーション）

**判定: ⚠️ 条件付き**

単調ではない。誤差はConfidence 0.2–0.4 の帯で最小（平均12.8点、n=211）になり、それより高い帯ではむしろ増える（0.4–0.6帯で17点/n=47、0.6–0.8帯で18.9点/n=8、0.8–1.0帯で8点/n=1）。そもそもConfidenceが0.4以上に達したサンプルは全体の7%しかなく、「Confidenceが高い＝信頼してよい」という画面上の約束は、実際にはほとんど検証されない領域にある。

## E8. 更新式を替えれば直るのか、それとも証拠量が足りないのか

**判定: ⚠️ 条件付き**

## E10. 証拠が増えるとConfidenceは上がるのか、下がるのか

**判定: ❌ 成立しない**

Confidenceは証拠7.5件で0.2686に達したあと下降し、60件では0.0009まで落ちる。原因は矛盾ペナルティの累乗で、1要素あたりの未解決矛盾が100.7件に増えるため。矛盾は positive×negative の総当たりで生成されるので証拠件数の2乗で増え、ペナルティ (1−0.25·severity) がその回数だけ掛かる。結果として「終了条件 conf ≥ 0.75」は対話を延ばすほど遠のく。

| 指標 | 値 |
|---|---|
| `peak_confidence` | 0.2686 |
| `peak_at_evidence_per_element` | 7.5 |
| `final_confidence` | 0.0009 |
| `final_unresolved_per_element` | 100.7 |
